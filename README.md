# 任务时钟

本地 Codex 插件。打开一次侧边栏实时面板后，自动显示本机最近的任务轮次：状态、已用时间、预计剩余区间和预计结束时间。一个对话中的每次执行分别计时，结束一轮不等于整个项目完成。

## 使用

安装后在 Codex 中输入“打开任务时钟”。插件的 `eta_panel` 工具返回面板链接，代理用 `open_in_codex` 在右侧打开。页面每 2 秒更新，日志发现每 5 秒运行。钩子生效后，在每次任务开始时提供简短上下文，请代理自动打开或复用当前聊天的面板，并在有合理依据时填写剩余时间区间；该步骤依赖代理遵循上下文、以及宿主提供打开面板的工具，不能保证每次都有估算。

也可直接执行 `python runtime.py panel` 获取链接。`python runtime.py status` 输出状态 JSON。

生命周期钩子需要在 Codex 的 Hooks 设置中由用户审核并信任，安装本身不授予钩子信任。插件不会修改信任记录。尚未信任时仍可从本机近期 JSONL 日志尽力发现任务；日志不是稳定接口，云端或不落本机日志的任务无法覆盖。面板需保持打开；没有使用未公开接口修改 Codex 原生任务栏，也不承诺自动为每个新窗口打开标签页。

## 时间的含义

- 代理估算：通过 `eta_set_estimate` 写入**从现在起**的剩余秒数区间，显示依据；超过上界后显示“需要重新估算”。
- 历史估算：同一类别、同一模型，且总耗时超过当前已用时间的已完成轮次至少 5 个，显示其剩余耗时的 20%–80% 经验分位区间。这不是经校准的置信区间。类别仅靠标题关键词粗分，不能保证任务复杂度可比。
- 样本不足：显示“暂无法估算”；等待批准时暂停显示 ETA；15 分钟无新事件时标记“状态待确认”。它可能仍在执行长工具，插件不会把静默当作已完成。
- 中断和未知轮次不进入完成耗时样本。人工等待会影响历史耗时，完成时间受外部操作影响。

## 本地数据与资源

无第三方依赖，无模型请求，无网络外发。仅监听 `127.0.0.1` 的随机端口；数据接口需要随机令牌。令牌位于链接片段，读取后从地址栏移除。勿分享面板完整链接。

数据写到 `~/.codex/task-eta/`，不更改 Codex 会话或数据库。保存任务标题前 100 字、会话/轮次 ID、时间、类别、模型、工具名称和估算依据；不保存工具参数、命令输出或完整对话。可用 `CODEX_ETA_DATA` 改写插件数据位置。

日志适配器查看最近 3 个日志日期目录中最新的 40 个文件，每文件每轮最多读取约 2 MB；启动时大文件从尾部读取，因此跨越截断位置的轮次可能无法恢复。只积累实际观察到的完整轮次，历史覆盖有限。服务在当前用户进程中后台运行，不注册开机启动。

停止：读取 `~/.codex/task-eta/service.json` 中的 PID，核实该 PID 的命令行是本插件的 `runtime.py serve` 后停止它。卸载用 `codex plugin remove codex-task-eta@task-clock-local`；数据文件保留，可自行删除。关闭网页不停止服务。

## 开发与验证

`python -m unittest discover -s tests -v` 验证剩余时间、超时、等待、中断、乱序事件和日志增量读取。`python tests/smoke.py` 在独立临时目录验证真实 MCP 子进程、HTTP 认证与实时状态。

工具索引：`runtime.py` 提供生命周期记录、保守的历史耗时估算、MCP 工具和本地面板服务；`dashboard.html` 为实时界面。已检查 Codex 生命周期钩子、插件运行时和现有插件能力：它们能提供事件与本地进程，但不提供任务剩余时间计算和持续显示面板，因此新增此实现。

官方接口参考：[插件打包](https://developers.openai.com/plugins/build/plugins)、[生命周期钩子](https://learn.chatgpt.com/docs/hooks)。
